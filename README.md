# PumpLog

短時間で迷わずトレーニングを記録し、前回の自分との比較や部位ごとの負荷を確認できる iOS 筋トレ記録アプリです。

コンセプトは **「記録を最小限に。前回の自分を超える。」**。トレーニング中の操作回数を減らすため、前回値の再利用、種目のタブ切り替え、セット完了後の休憩タイマーを中心に設計しています。

## 対応状況

| 項目 | 内容 |
|---|---|
| プラットフォーム | iOS（SwiftUI） |
| 保存方式 | SwiftData による端末内保存 |
| 通信 | 通常の記録操作では外部サーバーへ送信しない |
| UI | ダークテーマ、オレンジのアクセントカラー、iOS 標準の操作感 |
| 主要タブ | Home / History / Body / Setting |
| 状態 | Phase 1（ローカル保存版） |

## 主な機能

### Home

- トレーニングを開始・再開する
- 部位を複数選択して、その部位の種目をまとめて選ぶ
- Home からトレーニングメニュー（テンプレート）を作成する
- メニュー作成中に新しい種目を追加する
- 保存したメニューからワンタップでトレーニングを開始する
- 保存したメニューをスワイプまたは長押しメニューから削除する
- 最近の記録を確認する

### Workout

- 複数種目を横方向のタブで切り替える
- 種目ごとに重量・回数を入力する（回数のみの種目にも対応）
- ホイールピッカーで重量と回数を素早く変更する
- 前回の記録を初期値として表示する
- セットを追加、編集、複製、削除する
- 種目を追加・削除・切り替えする
- セット完了後に休憩タイマーを起動する
- タイマーの残り時間を滑らかに表示する
- タイマーをタップして分・秒を編集し、30秒単位で延長・短縮する
- 休憩終了時は振動のみで通知する（音は鳴らさない方針）
- セット一覧だけをスクロールし、トレーニング終了ボタンは下部に固定する
- 途中で画面を離れても、アクティブなトレーニングを Home から再開する

### Result

トレーニング完了後に、日付、部位、所要時間、種目数、総セット数、自己ベスト（PR）を確認できます。

### History

- カレンダーでトレーニング日を確認する
- 月の移動と日付の絞り込みを行う
- 種目名・部位で検索する
- 保存済みの記録を開いてセットを編集・削除する
- 記録日を編集する
- 履歴をスワイプして削除する（確認ダイアログ付き）
- アプリ再起動後も完了済みの記録を復元する

### Body

- 今日・今週・今月のトレーニング負荷を部位別に集計する
- 2D の部位マップで負荷のある部位を確認する
- `BodyAnatomyLicensed.bundle` の 3D 筋肉モデルを表示する
- トレーニング履歴に応じて対象部位をハイライトする

### Setting

- 休憩終了時の振動をオン・オフする
- トレーニング中に画面をスリープさせない設定を切り替える
- 3D モデルの出典、ライセンス、加工内容を確認する
- 初期休憩時間、重量単位、バックアップなどは今後追加予定です

## 画面と遷移

```text
ContentView
├─ Home
│  ├─ トレーニング開始
│  │  ├─ 部位を選択
│  │  ├─ 種目を選択・追加
│  │  └─ Workout
│  ├─ 保存したメニュー
│  │  └─ Workout
│  └─ 最近の記録 → History 詳細
├─ History
│  ├─ カレンダー・検索
│  └─ 記録詳細 → セット編集・削除 / 日付編集
├─ Body
│  └─ 期間別の部位負荷・3D 表示
└─ Setting
   └─ アプリ・トレーニング設定
```

Home のトレーニング開始からは、次の経路で進みます。

```text
部位を選択 → 種目を選択 → Workout → Result → Home
```

Workout 中に戻る操作を行った場合は、種目選択状態を保ったまま種目選択画面へ戻ります。Home タブへ切り替えた場合は、古いナビゲーションスタックを閉じて、アクティブなトレーニングを再開できる状態にします。

## 基本操作

### 初回起動

1. アプリを起動すると、標準種目が端末内データベースへ登録されます。
2. Home の「トレーニングを開始」をタップします。
3. 部位を1つ以上選択し、「次へ」をタップします。
4. 種目を確認し、必要なら種目を追加・削除して「次へ」をタップします。

標準種目には、ベンチプレス、インクラインダンベルプレス、ケーブルフライ、ラットプルダウン、シーテッドロー、ショルダープレス、サイドレイズ、ダンベルカール、プッシュダウン、スクワット、レッグプレス、クランチが含まれます。

### セットを記録する

1. Workout 画面で種目タブを選びます。
2. 重量と回数をホイールピッカーで設定します。
3. 「SET COMPLETE」をタップします。
4. 入力したセットが一覧に追加され、休憩タイマーが始まります。
5. 休憩が終わったら、次のセットを入力します。

前回記録がある場合は、同じ種目・同じセット番号の重量と回数を初期値として再利用します。履歴がない場合は重量 20 kg、回数 8 回が初期値です。重量は 0〜500 kg、回数は 1〜100 回の範囲で扱います。

### セットを編集・削除する

- セット行をタップして編集シートを開きます。
- 編集後に保存すると、そのセットだけが更新されます。
- セットの削除は確認操作を経て実行します。
- 削除後はセット番号を詰め直し、表示と保存データの順序を一致させます。

### 種目を切り替える・追加する

- Workout 上部の種目タブをタップすると、入力中の種目を切り替えられます。
- 種目追加シートで未登録の種目を選ぶと、現在のトレーニングへ追加されます。
- 追加した種目は同じトレーニング内で重複しません。
- 不要な種目は Workout の編集操作から削除できます。

### 休憩タイマーを編集する

- タイマーの秒数表示をタップすると、分・秒を直接編集できます。
- 「−30秒」「＋30秒」で短縮・延長できます。
- タイマーが 0 秒になった後でも、＋30秒で再開できます。
- Setting の「休憩終了時に振動」で通知方法を変更できます。音声通知は使用しません。

### トレーニングを終了する

1. セットを必要なだけ記録します。
2. 画面下部に固定された「トレーニング終了」をタップします。
3. 完了確認後、Result 画面でサマリーを確認します。
4. Home に戻ると、完了済みのトレーニングが最近の記録に表示されます。

未入力の種目や無効な重量・回数がある場合は完了できません。途中でキャンセルした場合は、完了済みの履歴は作成されません。

### メニューを作成する

1. Home 下部の「メニューを作成」をタップします。
2. メニュー名を入力します（例：胸の日）。
3. 種目を複数選択します。
4. 必要なら「種目を追加」から新しい種目を作成します。
5. 「保存」をタップします。
6. Home に表示されたメニューの「開始」をタップすると、その種目構成で Workout を開始できます。

保存済みメニューを削除する場合は、メニュー行を左へスワイプするか、長押しして「削除」を選びます。誤操作防止のため確認ダイアログを表示します。

### History を確認・編集する

1. History タブを開きます。
2. カレンダーの日付を選ぶか、種目名・部位を検索します。
3. 記録行をタップして詳細を開きます。
4. セットをタップして編集・削除します。
5. 日付を変更する場合は、詳細画面の日付編集を使います。
6. 履歴そのものを削除する場合は、一覧を左へスワイプして削除します。

削除した履歴とそのセットは端末内データベースから削除されます。削除前には確認ダイアログが表示されます。

## 詳細設計

### アーキテクチャ

PumpLog は SwiftUI を画面表示に、SwiftData を永続化に使用します。画面固有の状態は View または ViewModel が持ち、複数画面にまたがるデータは SwiftData のモデルを通じて共有します。

```text
SwiftUI View
   ↓ user action / binding
ViewModel または画面の操作メソッド
   ↓ validation / state transition
SwiftData ModelContext
   ↓ save
端末内の SwiftData ストア
```

### SwiftData モデル

| モデル | 役割 | 主な属性 |
|---|---|---|
| `Phase1Exercise` | 種目マスタ | `name`, `muscleGroup`, `recordType`, `weightStep`, `restDuration`, `isArchived` |
| `Phase1Workout` | 1回のトレーニング | `startedAt`, `endedAt`, `status`, `restEndAt`, `selectedWorkoutExerciseID` |
| `Phase1WorkoutExercise` | トレーニング内の種目 | `orderIndex`, `isCompleted`, `sets`, `exercise` |
| `Phase1WorkoutSet` | 1セットの記録 | `setNumber`, `weight`, `reps`, `completedAt`, `updatedAt` |

リレーションは、`Workout → WorkoutExercise → WorkoutSet` の親子構造です。Workout を削除すると配下の種目とセットも削除されます。Exercise は過去履歴から参照される可能性があるため、通常の管理ではアーカイブを優先し、履歴との関係を壊さないようにします。

### 入力値と整合性

- 種目名は前後の空白を除去して保存します。
- 種目の重量刻みは 0.1 kg 未満にならないよう補正します。
- 休憩時間は 0〜600 秒に制限します。
- 重量は 0〜500 kg、回数は 1〜100 回に制限します。
- 完了済みセットだけを履歴・負荷集計・PR 判定の対象にします。
- 同一のアクティブ Workout は最新の1件を再開対象にします。
- 種目やセットの削除・編集後は、選択中 ID と表示順を再調整します。

### 前回値と PR

`Phase1PreviousRecordService` が、今回より前に完了した最新の Workout から対象種目のセットを検索します。同じセット番号があればその値を、なければその種目の最後のセットを初期値にします。

`Phase1PRService` は、重量、同重量での回数、回数のみ種目の最大回数を過去履歴と比較します。過去履歴がない最初の記録は PR 通知の比較対象にしません。

### 期間別の部位負荷

Body タブでは、完了済みセットを今日・今週・今月の期間で絞り、種目の部位グループごとにセット数を集計します。集計結果は 2D 部位マップと 3D 表示へ渡します。データがない部位は未記録として扱います。

## コード構成

```text
pumplog_ios/
├─ pumplog_iosApp.swift          アプリ起動と SwiftData コンテナ
├─ ContentView.swift             ルート遷移、Home、History、Workout、Result、Setting
├─ Phase1Models.swift             SwiftData モデルと列挙型
├─ Phase1Services.swift           初期データ、前回値、PR、Workout 復元
├─ Phase1Migration.swift          旧形式データからの移行
├─ Phase1UIFoundation.swift       共通カラー、ボタン、ヘッダー、検索欄
├─ Phase1BodyTab.swift            Body タブと期間別集計
├─ Body3DView.swift               WKWebView と 3D モデルの橋渡し
├─ MuscleMapView.swift            2D 部位マップ
├─ ViewModels.swift                画面状態・分析ロジックの ViewModel
├─ WorkoutAnalytics.swift          種目推移・自己ベスト集計
├─ WorkoutCalendarView.swift       カレンダー表示
├─ ProgressView.swift              成長表示
└─ BodyAnatomyLicensed.bundle/     3D モデルとライセンス notices

pumplog_iosTests/
└─ Phase1WorkoutViewModelTests.swift  Workout の入力・保存に関するテスト

docs/
├─ requirements.md                要件定義
├─ detailed-design.md             詳細設計
├─ code-structure.md              コード構成と変更方針
└─ figma-design-brief.md          Figma デザイン仕様
```

画面固有の実装は対象画面のファイルに置き、複数画面で共通する UI・表示ルールは `Phase1UIFoundation.swift` に集約します。SwiftData の読み書きや集計ロジックは ViewModel または Service に置き、画面から直接重複実装しない方針です。

## 開発・確認方法

1. `pumplog_ios.xcodeproj` を Xcode で開きます。
2. `pumplog_ios` スキームを選びます。
3. シミュレーターまたは接続した iPhone を実行先にします。
4. ▶︎（Run）でビルド・起動します。
5. 変更後は、Workout の開始、セット追加、編集・削除、完了、History の編集・削除、アプリ再起動を確認します。

実機で確認する場合は、Apple ID の署名設定、接続端末の信頼、必要に応じた開発者モードが必要です。署名やプロビジョニングの設定は、開発環境ごとに異なるため Xcode の Signing & Capabilities で確認してください。

## 3D モデルとライセンス

Body タブの 3D モデルは `BodyAnatomyLicensed.bundle` に同梱しています。モデル本体と関連アセットには出典ごとのライセンス条件があるため、配布時は必ず同梱 notices とライセンス本文を確認してください。

現在のアプリには次の情報を Setting 内と bundle 内 notices に記載しています。

- Body Anatomy 3D Viewer（hpfrei）および Z-Anatomy contributors への帰属
- CC BY-SA 4.0 のライセンスリンク
- アプリ表示用に行った加工の説明
- Three.js（MIT）および Draco（Apache License 2.0）の notices

CC BY-SA 4.0 の素材を改変・再配布する場合は、帰属、ライセンスへのリンク、変更内容の表示、同ライセンス条件の確認が必要です。App Store で配布する場合も、アプリ内からライセンス情報へアクセスできる状態を維持してください。最終的な配布可否は、同梱されるすべての素材のライセンスと Apple の審査要件を確認したうえで判断します。

## 現在の制約と今後の候補

- アカウント、クラウド同期、バックアップ、データ書き出しは未実装です。
- 初期休憩時間や重量単位の全体設定は今後追加予定です。現状は種目ごとの休憩時間と重量刻みを使用します。
- テンプレートの編集・並べ替えは今後の拡張候補です。現状は作成、利用、削除に対応しています。
- 3D 表示はモデル読み込み時間や端末性能の影響を受けます。
- 通知は振動のみで、音声通知は使用しません。
