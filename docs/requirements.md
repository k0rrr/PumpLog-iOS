# PumpLog 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| 文書名 | PumpLog 要件定義書 |
| 版 | 0.1 |
| 作成日 | 2026-08-29 |
| 対象 | iOS 筋トレ記録アプリ |
| 対象バージョン | フェーズ1（ローカル保存版） |

## 2. 目的

筋力トレーニングの記録を短時間で入力でき、過去の記録や成長を確認しやすくする。入力した種目情報を利用して、将来的には身体部位ごとの負荷をアバター上で可視化する。

## 3. 想定利用者

- 自分の筋トレを継続的に記録したい個人ユーザー
- 種目、重量、回数、セット数を日々入力するユーザー
- 前回値やテンプレートを使って入力の手間を減らしたいユーザー

## 4. 対象範囲

### 4.1 フェーズ1の対象

- トレーニング記録の作成、複数種目の管理
- 種目の追加・編集・削除・並べ替え
- セットの追加・複製・編集・削除
- 前回値の自動入力、休憩タイマー
- 種目ごとの入力タブ
- トレーニング完了時の履歴保存と入力状態の初期化
- 履歴の閲覧、検索、期間・部位フィルター、編集、削除、カレンダー
- 重量、回数、総負荷量、自己ベストの確認
- 筋肉部位マップによる負荷表示
- トレーニングテンプレートの作成、利用、削除
- デバイス内へのデータ保存

### 4.2 将来拡張

- 身体アバターの表示と負荷強度による着色
- テンプレートの編集、並べ替え
- iCloud等による複数端末同期、バックアップ、データエクスポート
- 通知、目標設定、進捗リマインダー

## 5. 前提・制約

- iOSアプリとして提供する。
- フェーズ1ではログインを必須にしない。
- フェーズ1の保存先は端末内とし、基本操作はオフラインで可能とする。
- 重量はkg、回数は整数で入力する。
- 日付は年月日のみを扱い、時刻は入力・表示しない。
- 1回のトレーニングは複数種目で構成できる。
- 種目には大分類と詳細部位を設定する。

## 6. 用語定義

| 用語 | 定義 |
|---|---|
| 種目 | ベンチプレス、スクワット等のトレーニング単位 |
| セット | 1種目に対する重量・回数・種別の記録 |
| トレーニング | 同一日に行った複数種目のまとまり |
| 履歴 | 完了して保存されたトレーニング記録 |
| テンプレート | 頻繁に使う複数種目の組み合わせを保存したメニュー |
| 総負荷量 | 重量 × 回数をセット単位で合計した値 |
| 詳細部位 | 胸上部、広背筋、大腿四頭筋などの表示単位 |

## 7. 機能要件

### FR-001 記録の開始

- 記録タブで日付を選択できる。
- 日付は年月日を数字で表示する。
- 登録済み種目を追加できる。
- 種目追加画面から新しい種目作成画面へ遷移できる。
- 同じ種目を同一トレーニングへ重複追加しない。

### FR-002 複数種目の入力

- 追加済みの全種目を保持する。
- 種目ごとのタブを表示する。
- タブ切り替えで対象種目のセット入力フォームを表示する。
- 種目を切り替えても入力済みセット、メモ、前回値を保持する。

### FR-003 セット記録

- 重量と回数を入力してセットを追加できる。
- 重量は0以上、回数は1以上とする。
- 重量の小数点としてピリオドとカンマを許容する。
- 「ウォームアップ」「通常」を選択できる。
- 追加後は入力欄を空にし、キーボードを閉じる。
- 既存セットを編集、複製、削除できる。
- 最後のセットと同じ内容を追加できる。

### FR-004 前回値

- 種目追加時、最新履歴のセットを初期値として表示する。
- 前回値は今回の下書きとしてコピーし、今回の変更が過去履歴へ影響しない。

### FR-005 休憩タイマー

- 60、90、120、180、300秒から選択できる。
- 開始、30秒延長、終了ができる。
- 実行中の残り時間を画面下部に表示する。
- トレーニング完了後はタイマーを初期化する。

### FR-006 トレーニング完了

- 全種目に1セット以上あり、重量・回数が有効な場合のみ完了できる。
- 完了時、種目ごとの記録を履歴として保存する。
- 同一トレーニングの履歴には同一セッションIDを付与する。
- 完了後はセット追加フォーム、セット一覧、選択種目、入力値、キーボード、タイマーを初期状態に戻す。
- 自己ベストを更新した場合は通知する。
- 条件を満たさない場合は保存せずエラーを表示する。

### FR-007 テンプレート

- テンプレート名と複数種目を指定して作成できる。
- テンプレート名は必須かつ重複不可とする。
- 記録画面からテンプレートを選択して開始できる。
- 選択画面には用途説明、テンプレート名、種目数、種目名を表示する。
- 適用時は種目をまとめて下書きへ追加し、先頭種目を選択する。
- 種目追加画面を開いて何も選ばず閉じても、既存種目を削除・変更しない。
- 種目タブを切り替えてテンプレート内の各種目を入力できる。
- テンプレートを削除できる。

### FR-008 種目管理

- 種目を新規作成、編集、削除、並べ替えできる。
- 種目名は必須かつ重複不可とする。
- 大分類、器具、詳細部位を登録できる。
- 種目削除時は下書きとテンプレートの参照も整理する。

### FR-009 履歴

- 保存済み履歴を日付の新しい順で表示する。
- 日付、種目名、メモで検索できる。
- 過去7日、30日、90日、全期間で絞り込める。
- 大分類で絞り込める。
- 履歴を編集、保存、削除できる。
- カレンダーで実施日を確認できる。

### FR-010 成長分析

- 種目を選択して推移を表示できる。
- 重量、回数、総負荷量を時系列で確認できる。
- 種目ごとの自己ベストを表示できる。

### FR-011 身体部位表示

- 種目の対象部位から部位別負荷を集計する。
- 部位ごとの負荷状態を身体マップへ反映する。
- データがない部位は未記録として表示する。
- 将来のアバター表示へ移行できる安定した部位IDを使用する。

## 8. 非機能要件

### NFR-001 使いやすさ

- 記録開始から最初のセット追加までの操作を少なくする。
- 主要操作のボタン名は日本語で具体的にする。
- テンプレート利用時に追加される種目を事前確認できる。

### NFR-002 性能

- 履歴1,000件未満の通常利用で、画面操作に目立つ遅延を発生させない。
- グラフ・部位集計の表示で過度な待ち時間を発生させない。

### NFR-003 信頼性・整合性

- アプリ再起動後も保存済みデータを復元できる。
- 不正なセットを履歴へ保存しない。
- 存在しない種目IDを新規記録へ使用しない。
- 旧データ形式を可能な範囲で移行する。

### NFR-004 プライバシー

- フェーズ1では外部サーバーへデータを送信しない。
- データは端末内のアプリ領域に保存する。

### NFR-005 保守性

- 画面、状態管理、分析ロジック、モデルを分離する。
- 部位は文字列の直接比較に依存せず、列挙型または安定IDで管理する。

## 9. 優先度と実装順

| 優先度 | 対象 | 内容 |
|---|---|---|
| P0 | 記録・データ | 種目追加、セット記録、完了保存、初期化、端末保存、検証 |
| P1 | 入力効率化 | 前回値、セット複製、休憩タイマー、種目タブ |
| P1 | 履歴・分析 | 検索、フィルター、編集、カレンダー、グラフ、自己ベスト |
| P1 | メニュー | 種目管理、テンプレート作成・利用・削除 |
| P2 | 可視化 | 詳細部位マップ、身体アバター、負荷強度表現 |
| P2 | 拡張 | 同期、バックアップ、通知、目標管理 |

## 10. 受け入れ条件

- 2種目以上を追加し、タブを切り替えて各種目へセットを入力できる。
- テンプレートから複数種目を開始しても、種目が欠落しない。
- 種目追加画面を開いて何も選ばず閉じても、追加済み種目数が変わらない。
- 有効な記録を完了すると履歴に保存され、記録画面が空の初期状態になる。
- 無効な重量・回数では完了できない。
- 再起動後も種目、履歴、テンプレートが保持される。
- 履歴検索・フィルター・編集・削除が機能する。
- 成長画面と身体部位表示が履歴データと一致する。
